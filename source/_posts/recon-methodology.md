渗透测试中流传着一句话：**「信息收集做得越好，后面越轻松」**。这篇笔记整理授权测试场景下信息收集的框架、思路和整理方法。

<!-- more -->

> 前置提醒：所有测试行为必须在 **书面授权范围** 内进行，明确目标、时间窗口和测试边界。未经授权的扫描和探测是违法的。

## 一、信息收集的目标

信息收集回答三个问题：

1. **有什么**：目标到底有多少资产（域名、IP、端口、应用、小程序、APP……）
2. **是什么**：每个资产用什么技术（中间件、框架、版本、WAF）
3. **怎么进**：哪些面是攻击面（登录口、API、后台、测试环境、历史遗留）

安全界有个经典结论：**被攻破的往往不是「正面」的主站，而是被遗忘的测试站、过期的子域名、没人维护的老系统**。所以资产的「全」比「深」更重要。

## 二、被动收集 vs 主动收集

| 类型 | 特点 | 例子 |
| ---- | ---- | ---- |
| 被动收集 | 不直接触碰目标，不产生流量 | 搜索引擎、备案信息、GitHub 泄露、证书透明度日志 |
| 主动收集 | 直接与目标交互，会在对方日志留下痕迹 | 扫描、探测、目录爆破 |

一般顺序是 **先被动后主动**：先用公开信息画出大概轮廓，再有针对性地主动验证。

## 三、收集的内容清单

### 1. 域名与子域名

- 备案信息、WHOIS、证书透明度日志（crt.sh）
- 搜索引擎语法（`site:`、`inurl:` 等）
- 子域名字典枚举 → 再做解析验证

### 2. IP 与端口

- 域名解析、CDN 识别（有 CDN 时直接 IP 测试意义有限）
- 端口扫描：关注 Web（80/443/8080/8443）、数据库、远程管理、中间件默认端口
- 反查：同 IP 其他站点

### 3. Web 指纹

- 服务器/中间件类型与版本（响应头、报错特征）
- 前端框架、JS 框架、WAF 识别
- CMS / 开源程序识别（特征文件、页面关键字）

### 4. 应用与业务

- 登录入口、注册、找回密码、上传点
- API 文档、接口路径（前端 JS 里常有惊喜）
- 移动端 APP / 小程序（往往比 Web 端少一些防护）

### 5. 人在哪

- 公开的联系邮箱、员工信息（用于钓鱼演练等 **授权场景**）
- GitHub / Gitee 上的代码泄露（内部地址、密钥、注释里的口令）

## 四、整理成「资产清单」

收集的结果一定要落表，推荐的字段：

```
资产地址 | 类型 | 负责人 | 技术栈 | 开放端口/服务 | 备注 | 风险初判
```

有了这张表，后续的漏洞验证、报告输出都有了依托；复测时也能快速对比资产变化。

## 五、方法论参考

- **PTES**（Penetration Testing Execution Standard）：把信息收集放在「情报收集」阶段
- **OWASP WSTG**：Web 安全测试的完整 checklist
- **ATT&CK**：把收集到的点映射到战术/技术矩阵

## 六、踩坑记录

- 扫描时注意 **控制速率**，避免影响业务，也不要把对方扫挂了；
- 记录每一次探测的 **时间和目标**，报告里要写清楚，也方便自证合规；
- 不在授权范围内的资产，**即使发现了也不要碰**，按约定流程上报。
